01 / The research question

Can a model learn the defect,
not just the project?

Security archives contain many vulnerable functions, but few matched examples of what changed when the defect was fixed.

01

The source shortcut

When a data source contributes only vulnerable examples, its formatting and naming conventions can become a shortcut for the label.

02

The patch sensitivity gap

A model can rank functions well overall while assigning a higher risk score to a repaired function than to its vulnerable original.

02 / The approach

Compare locally.
Score individually.

Fix commits supply the comparison. Reference data anchor the classification task. Both update one shared model.

01PMC

Build matched groups

Reconstruct the vulnerable function, its patched version, and up to two unchanged functions from the same file.

VulnerablePatchedSame-file context × 2
2,829 groups · verified file snapshots
02HYB

Train two linked tasks

Classify functions from the reference pool. Rank the vulnerable member above the other members of each matched group.

Classification+Group ranking
One shared Qwen3.5-4B backbone
03INFERENCE

Prioritize review

Score one function at a time, then sort and select functions within a review budget for deeper analysis.

One forward pass per model and function

Patched and unchanged functions provide weak supervision, not independently verified benign labels. External groups contribute to ranking only; the classification term uses the reference pool.

↳

Evaluation separates protected splits from training by project, CVE, fix commit and code similarity. The manuscript reports project-cluster bootstrap intervals and patch-pair tests. Dataset labels and commit-derived supervision retain their original limitations.

A role in the review workflow

A first pass.
A human decision.

The intended use is to rank changed functions before deeper review with static analysis, rules or a security reviewer.

The work evaluates historical functions and fixes. Live pull-request deployment, new vulnerability discovery and comparative throughput have not been demonstrated. A score prioritizes attention; it does not establish that code is safe.
